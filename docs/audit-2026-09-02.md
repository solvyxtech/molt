# Audit of 2026-09-02, and what it changed

A full audit of this repository, sourced through the live `.molt/` record as
well as the source, followed by two passes of fixes and a fine-tuning
framework. Everything below was reproduced against the built output before it
was fixed, and every fix ships with a test that was shown to go red without it.
This page exists so the next session — human or model — can start from the
state rather than re-derive it.

## Findings, in the order they mattered

1. **`work-proven` never covered a line.** The suite wrote lcov as
   `dist-test/src/*.js` with compiled line numbers; the ledger names
   `src/*.ts`; `coverageFor` matches by suffix. Fifteen receipts read
   "0 changed file(s) executed by the tests" and passed. Fixed with source
   maps (`tsconfig.test.json`, `--enable-source-maps` in `test-run.mjs`).
2. **The integrity ledger never read back the journal roots it bound.** A
   journal rewritten and re-chained verified clean with the same root of
   trust. `Integrity.verify` now resolves every bound root to an entry;
   `Integrity.verifyProject` is the one verdict both surfaces use — the
   window's button had skipped the journal half.
3. **Work done through `bash` was invisible to every ledger builtin.** A
   scratch script run with `node` deleted an assertion and the turn was
   accepted with `spec-intact: no test file was changed`; at `--yes`, `sed
   -i`, `cp`, `mv` do not ask. New builtin `tree-accounted` snapshots the
   working tree at turn start and refuses any change no tool wrote;
   `spec-intact` reads assertions from the snapshot too. Commandment 7 is
   tier 2.
4. **A turn that wrote nothing was accepted on the previous turn's write.**
   `files-changed` now has a turn floor (`BarContext.turnLedger`).
5. **ctrl+C during a bar check** produced a refused receipt, a billed request,
   and a killed check cached as a failure. `BarResult.cancelled`; nothing
   aborted is cached; the turn ends as cancelled.
6. `record-intact` passed on a corrupted evidence block in a later session;
   `molt verify` printed ok for zero-byte and garbage journals; `/shed` was
   never journalled; receipts listed every earlier turn's calls; the `tests`
   watch omitted `electron/**` and `ui/**`. All fixed.
7. **Stats were not reproducible from the receipts** (a phantom row from a
   reissued sequence number, priced dollars over unpriced acceptances, five
   answered questions counted as verified changes). Rows now carry
   `changed`, `ask`, `costEstimated`; `stats` dedupes by file and says what it
   does not count; `receipts --repair` backfills change counts from bodies.
8. Task criteria were unreachable headlessly: `molt run --criterion
   name=cmd --note "..."` now exists. `/attempts` and `/autoshed` exist on
   both surfaces. Docs that described a "Checks" tab, 805 tests and a grader
   that lives in another repository were corrected.

## Found afterwards, from real runs (2026-09-03)

9. **Elision was throwing away the prompt cache.** Dropping a superseded read
   from the middle of the transcript invalidates every cached token after it,
   so a step could save 400 tokens and pay 20,000. Elision now defers when the
   session is cached and the saving does not pay back within three steps, and
   a single low-reuse step no longer reports the cache as lost.
10. **A broken check was reported as a failing one.** A model sealed a
    criterion grepping a file that did not exist; grep exited 2, the bar said
    FAIL, and the model spent the turn creating the file to make the error go
    away. 127 and 126 are now reported as "did not run", a broken check is
    named as something no work can satisfy, a turn whose only unmet checks are
    broken stops at once rather than spending every attempt, and criteria are
    tried once at seal time. It still blocks — an unrunnable check is not a
    reason to accept a claim. See `docs/done-yml.md`, "Broken checks".

## Live-model evidence (mercury-2.5 via OpenRouter, about $0.11 total)

- Same prompt, same model: **accepted** on the pre-fix tree, **refused** on the
  fixed one (`work-proven`, never executed: 77, 205).
- The bash attack earned no receipt in three attempts; told to use `sed`, the
  model was refused by `work-accounted` naming the file.
- A `--criterion` ran on the receipt as `task:fmtbytes-checked`.
- A fix the bar **accepted** for finding 1 was wrong in its unit
  (stem-matching `.ts` to `.js`); that is what criteria are for.
- An ask-mode review with invented findings came back "verified" — now
  `answered`, and not a verified change.

## Decisions left open, deliberately

- `diff-covered` fails on a missing report but passes when every changed file
  is absent from it; `mutation` passes on zero mutations. One rule is needed.
- Whether an answered question should ever produce an "accepted" receipt.
- `assertionsIn` only sees assertions that start a line.

## The fine-tuning framework (`finetune/`)

`extract.mjs` turns every `.molt/` into mlx-lm rows (target: the bar's
verdict), deduped by receipt hash, split by session, with provenance.
`molt run --capture <dir>` records full redacted transcripts per attempt.
`generate.sh` makes labelled runs; a ten-run batch produced 18 captured
attempts, and the dataset stands at 68 unique receipts. First working fine-tune: Qwen3-4B-4bit,
60 iterations, validation loss 9.53 → 0.90, peak 5.8 GB on an M5/24 GB. The
two traps (NaN from a truncated target under `--mask-prompt`; Metal OOM) are
in `finetune/README.md`. The model proposes; the bar decides.
